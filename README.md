# 梦幻西游搬砖记录器

![图片](https://github.com/zhanyis/mhxy_tools_electron/blob/main/public/1jifushi.png)

## 开发

安装依赖后，先运行 `npm run prisma:generate` 生成数据库客户端，再运行 `npm run dev`。
构建和发布流程会自动生成 Prisma 客户端。本地数据存储为 SQLite，首次启动会迁移旧版 JSON 数据。

## 自动发布与更新

- 推送与 package.json 版本匹配的新稳定标签后，GitHub Actions 自动构建；Windows 安装包和更新资源校验成功后才公开 Release，其他平台失败不会阻断 Windows。
- 发布使用仓库内置 GITHUB_TOKEN，无需配置 RELEASE_TOKEN；请勿重复发布已公开的版本。
- 已安装应用启动后自动检查更新，也可点击右上角「检查更新」。用户确认后下载，下载完成后选择立即重启或退出时安装，请先保存记录。
- 发布步骤、必需附件和本地验证见 [发布指南](RELEASE_GUIDE.md)。

## 物价页：在线识屏

- 点击「识屏设置」→「选择屏幕 / 窗口」，优先选择游戏窗口。
- 在预览画面上拖动框选聊天 / 交易文字区域，在弹窗内打开「在线识屏」开关。支持简体中文及英文；可切换采样间隔、深色背景灰度增强和累计最低置信度。
- 首次使用需联网下载 OCR 模型，缓存在应用用户数据目录的 ocr-models 子目录中。后续本机识别，屏幕图像不会上传到云端。
- 当前画面和滚动累计文字分开展示。最近 60 秒重复出现的同一行会去重，累计保留最近 500 行，支持复制、导出文本；不会自动修改物价。
- 关闭弹窗只隐藏设置和结果，不影响屏幕捕获、模型加载和持续识别；重新打开可查看累计结果。关闭弹窗内的识屏开关或离开物价页会释放屏幕捕获和 OCR 线程；再次启用前需重新选择屏幕来源。
- 本应用窗口不会出现在可选来源中，运行时隐藏实时预览；整屏识别启动后自动收起弹窗。捕获整个显示器时仍需将本应用移出文字区域，避免自捕获。
- 精准录入不追求识别每一条：先检查原生画面清晰度，连续两次采样稳定后只识别一帧，完成报价提取后再采样。模糊或滚动中的画面跳过；报价输入使用独立的高置信度门槛（行 ≥85、非空词 ≥75），不受累计文字门槛降低影响。清晰度和 OCR 置信度只是筛选指标，不保证零误字，数字仍需人工确认。
- macOS 请在「系统设置 → 隐私与安全性 → 屏幕录制」中授权本应用，授权后重启；开发模式可能显示为 Electron。目标窗口请保持可见且不要最小化，避免将本应用识屏预览包含在识别区域中。
- OCR 按帧串行执行，实际速度取决于识别区域大小及设备性能；无法保证高速滚动零漏字。建议缩小框选区域、减慢滚动，并核对价格等关键数字。
- 运行识屏测试：`node --test tests/scrollingText.test.mjs tests/screenOcrLifecycle.test.mjs`，覆盖滚动去重、关闭弹窗后继续识别及停止清理。

## 喊话报价与单品趋势

### 人工解析配置

- 入口：物价 → 喊话报价 → 解析配置。按服务器保存规则，可搜索、新增、编辑、删除、启用 / 停用，支持 JSON 导出和追加导入，每个服务器最多200条规则。导入先校验全部内容，失败不会部分写入。物品须已存在于当前物价表。
- 规则不会因未采集、刷新、重启、修改物价或导入而被清空，不提供批量清空入口。删除时逐条展示规则、物品和服务器，必须点击「确认删除这一条」；取消、关闭窗口或服务器变更均不删除，其他规则和报价历史保留。
- 首次生成 / 新建规则默认关闭，按需启用关注的物品；已有启停设置不自动覆盖。编辑窗口提供「价格在前：30收物品」「价格在后：物品30」快捷正则，按当前名称 / 简称生成，自动填入测试样例，核对默认单位后保存；不会清空规则。价格在后且未写收购方向的文本仍需人工核对。
- 两个快捷按钮都支持同一物品的双向报价，适用于所有物品名称 / 简称，例如龙鳞规则可同时识别「30收龙鳞」「龙鳞30」。按钮不限制仅识别某一方向，测试框同时填入两种样例；无物品名的裸数字或其他物品不会被映射为当前物品。
- 价格在前也允许省略「收」，如「30龙鳞」；此时提示人工核对收购方向。旧规则不自动覆盖，需要在编辑窗口重新点击任一快捷正则、测试后保存；若勾选「必须写明收 / 收购 / 求购」，不含收的文本仍不会匹配。
- 所有弹窗限制在当前窗口高度内，正文在弹窗内部滚动，标题 / 底部操作保持可见；嵌套规则编辑、趋势、识屏及确认窗口同样适用，不滚动整页。
- 简称模式：选择物价单品，填写多个名称 / 简称，如「高级偷袭、高偷」，设置省略单位时使用万、千或原始 MHB，并选择是否要求原文出现收 / 收购 / 求购。每种物品和特殊报价格式都可单独配置，无需按商人配置。
- 表达式模式：使用 RE2 语法，不加 `/ /`，必须包含命名捕获组 `(?<price>...)`；可选单位组 `(?<unit>万|w|千|k|两)`。例如 `(?<price>[0-9]+)收牌子` 识别价格在前；`(?:高偷|高级偷袭)\s*(?<price>[0-9]+(?:\.[0-9]+)?)(?<unit>万|w)?` 识别价格在后。匹配会重复进行，一条喊话可以提取多个物品；同物品多档价格冲突则跳过，不猜选哪一档。
- 编辑窗口提供「测试匹配（不会入库）」，展示匹配物品、MHB 单价和原文。安全正则引擎不采用原生回溯，限制表达式长度和复杂度，不支持反向引用。规则只生成待确认报价，不自动入库或改基础物价。
- 首次为当前物价表生成可编辑默认规则：牌子 → 特赦令牌，高偷 / 高必 / 高连 / 高吸 / 高夜 → 对应高级兽决；这些简称裸价格默认按万。`335收牌子` → 3,350,000 MHB，`高偷4330` → 43,300,000 MHB。原文明确单位始终优先于默认单位，基础物价输入仍是原始 MHB。新增物价单品后可手动添加其解析规则。

### 自动采集与确认

- 在物价页打开「喊话报价」，设置服务器 / 分区。清晰稳定帧直接产生候选，不需要复制文本；同帧可续接换行，不跨帧继承内容。识别不清晰行、频道变化和系统公告作为边界。掉落公告、出售、未知物品、无价格、批量价和价格区间跳过；`高必d4320`、`335V收牌子` 等损坏数字不删字猜价。
- 不提取或保存独立的商人名称、游戏 ID，也不要求填写身份。已识别的频道 / 方括号昵称 / 昵称(ID) 前缀从报价正文移除；未识别格式仍可能留在原始文本中，不作为身份字段或去重依据。旧数据库保持不破坏，不做身份数据清除。
- 去重维度为服务器 + 本机日期 + 规范化喊话正文（全半角统一，连续空白合并）。同一天相同正文只录一次；原文不同、跨天或不同服务器可分别记录，不再按商人或单品限制每日一条。
- 候选为扁平可编辑表格，每页20条，最多100条，图片复用原物价。核对所有相关行的物品、价格、原文、单位和收购方向后，点击「确认喊话」会列出并原子保存同一喊话的全部待确认物品；不需要的行可先忽略。配置变化会清理旧候选并重解析当前帧，避免继续使用旧规则。
- 旧 TXT 测试 / 导入默认收起，按导入当天记录，不能恢复无时间戳文本的历史日期。误录报价可删除并重算统计，但仍保留原喊话当天的去重标记，避免其余物品重复统计。
- 每个单品显示历史最高 / 最低、最近两个有报价日均价变化；「价格趋势」显示最近30天均价 / 最高 / 最低及最近200条原文。无样本日期留空，统计仅代表人工确认的报价，不代表成交价或完整行情。
- 报价和规则保存在本机 SQLite，重启保留；旧报价历史和关键词幂等升级到新流程，原物价分类、初始化价格及图片不变。待确认队列仅存在当前页面。
- 回归测试：`node --test tests/shoutParsing.test.mjs tests/merchantQuotes.test.mjs tests/ocrQuality.test.mjs tests/itemImages.test.mjs tests/screenOcrLifecycle.test.mjs tests/scrollingText.test.mjs`。数据库测试使用临时 SQLite，不触碰用户数据。
